##  Project Overview

**nerd-space** is a fully self-hosted, production-grade homelab server built on an Intel NUC8 running Ubuntu Server 26.04 LTS. The goal of this project was to migrate all existing homelab services from a decommissioned HP laptop server onto a consolidated, purpose-built headless server node — and to deploy a full SIEM (Security Information and Event Management) platform with real endpoint monitoring.

This project demonstrates hands-on skills in Linux server administration, Docker containerization, network configuration, security hardening, and SIEM deployment — all directly applicable to SOC Analyst and Cybersecurity Analyst roles.

##  Wazuh SIEM Deployment

### Stack
- **Version:** Wazuh 4.14.0 (single-node Docker deployment)
- **Components:** Wazuh Manager + OpenSearch Indexer + Wazuh Dashboard
- **Data path:** `/mnt/data/docker-volumes/wazuh-siem/`

### Deployment Process

```bash
# Clone stable release
cd /mnt/data/docker-volumes
mkdir -p wazuh-siem && cd wazuh-siem
git clone https://github.com/wazuh/wazuh-docker.git -b main --single-branch .
git fetch --tags
git checkout tags/v4.14.0

# Generate SSL certificates
cd single-node
docker compose -f generate-indexer-certs.yml run --rm generator

# Deploy stack
docker compose up -d

# Monitor initialization (~2-3 minutes)
docker compose logs -f
```

### Access
- **Dashboard URL:** `https://192.168.254.10`
- **API:** `https://192.168.254.10:55000`

### Issues Encountered & Resolved

| Issue | Root Cause | Resolution |
|---|---|---|
| Wazuh 5.0.0 images not found | Main branch targets unreleased version | Checked out `tags/v4.14.0` |
| `wazuh-passwords-tool.sh` not found | Tool location changed in v4.14 | Created new admin user via dashboard UI |
| Default `admin` account undeletable | OpenSearch reserved user protection | Created `Admin` account with `all_access` + `admin` backend roles |
| Agent showing disconnected | `client.keys` out of sync after duplicate registration attempts | Removed agent via `manage_agents -r 001`, cleared `client.keys`, re-registered |
| Duplicate agent name error | Previous failed registration attempts left ghost entries | Cleared via `/var/ossec/bin/manage_agents` inside manager container |

### Agent Deployment

```bash
# On endpoint — install agent (generated by Wazuh dashboard wizard)
wget https://packages.wazuh.com/4.x/apt/pool/main/w/wazuh-agent/wazuh-agent_4.14.0-1_amd64.deb
sudo WAZUH_MANAGER='192.168.254.10' dpkg -i wazuh-agent_4.14.0-1_amd64.deb
sudo systemctl daemon-reload
sudo systemctl enable wazuh-agent
sudo systemctl start wazuh-agent
```

##  Firewall Rules (UFW)

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp        # SSH
sudo ufw allow 51820/udp     # WireGuard
sudo ufw allow 443/tcp       # Wazuh Dashboard (HTTPS)
sudo ufw allow 1514/tcp      # Wazuh agent communication
sudo ufw allow 1514/udp      # Wazuh agent communication
sudo ufw allow 1515/tcp      # Wazuh agent registration
sudo ufw allow 9200/tcp      # Wazuh Indexer
sudo ufw allow 55000/tcp     # Wazuh API
```

##  Security Hardening Applied

-  SSH key-based authentication only
-  Root login disabled (`PermitRootLogin no`)
-  Password authentication disabled (`PasswordAuthentication no`)
-  UFW firewall enabled with default deny incoming
-  Fail2ban configured (SSH jail, max 3 retries)
-  Non-default admin account created in Wazuh
-  Static IP via Netplan (no DHCP dependency)
-  ext4 filesystem with tune2fs resilience settings
-  Timeshift backups (planned)
-  UPS for clean shutdown on power loss (recommended — previous NUC suffered ext4 corruption from power blip)
